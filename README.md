# ONEFLOW PRO BUSINESS — מחשבון אומדן

מחשבון אומדן עלויות למיישמים. אתר סטטי, ללא שרת וללא בסיס נתונים.

## קבצים

| קובץ | תפקיד |
|---|---|
| `index.html` | המחשבון כולו |
| `pricing.json` | **המחירון הרשמי** — מה שרואה מי שנכנס בלי קישור אישי |
| `pricing-<שם>.json` | מחירון אישי של מיישם |
| `logo.png` | הלוגו הראשי בכותרת ובמסמך המופק |
| `oneflowlogo.png` | לוגו המוצר, מוצג במסמך המופק |

## מחירון לכל מיישם

לכל מיישם קישור אישי, והוא טוען את קובץ המחירון שלו:

```
https://<כתובת-האתר>/?p=moshe   ->   pricing-moshe.json
https://<כתובת-האתר>/?p=dana    ->   pricing-dana.json
https://<כתובת-האתר>/           ->   pricing.json  (המחירון הרשמי)
```

המזהה בקישור מסונן לאותיות אנגליות קטנות, ספרות, מקף וקו תחתון בלבד.

### להקים מחירון למיישם חדש

1. פתח את המחשבון, היכנס להגדרות (גלגל השיניים) וערוך את המחירים.
2. לחץ **ייצא** — יורד קובץ JSON.
3. שנה את שמו ל-`pricing-<שם>.json` והעלה אותו לתיקייה הראשית של הפרויקט.
4. שלח למיישם את הקישור `?p=<שם>`.

שדות שכדאי למלא בקובץ:

| שדה | תפקיד |
|---|---|
| `label` | שם המחירון, מוצג בכותרת ובמסך ההגדרות |
| `implementerName` | שם המיישם, ממולא אוטומטית באומדן |
| `publishedAt` | חותמת תאריך, נוצרת אוטומטית בייצוא |

### לעדכן מחירון קיים

ערוך, ייצא, והחלף את הקובץ הקיים. המיישם מקבל את העדכון בפתיחה הבאה —
הקובץ נטען ללא מטמון.

## שינוי מקומי אצל מיישם

מיישם שעורך מחירים במסך ההגדרות יוצר **עותק מקומי** בדפדפן שלו בלבד.
התגית בכותרת מתחלפת ל־"מחירון מקומי", וכפתור במסך ההגדרות מחזיר אותו
למחירון שמגיע מהקישור. העותק המקומי אינו מגיע לאף אחד אחר ואינו עובר
בין מכשירים.

## חיבור למסד נתונים

עד לחיבור, המערכת עובדת במלואה מול אחסון הדפדפן — מחוללת מחירונים, מצפינה
סיסמאות ושומרת גרסאות ואומדנים. החיבור הופך את הנתונים לזמינים מכל מכשיר
ולכל המיישמים, ומעביר את אימות הסיסמה לשרת.

### הקמת השרת ברנדר

התיקייה `server/` מכילה שרת Node עצמאי (ללא תלויות מלבד `pg`) המממש את
ה-API במלואו: מחירונים, סיסמאות, גרסאות, אומדנים ולידים. `render.yaml`
שבשורש הריפו מגדיר את שני השירותים הנדרשים - מסד PostgreSQL ושירות Web
להרצת השרת. ברנדר: **New → Blueprint** → בחירת הריפו → רנדר קורא את
`render.yaml` ומציע להקים את שניהם. יש להזין `ALLOWED_ORIGIN` (כתובת
האתר הסטטי) - שאר המשתנים מוגדרים אוטומטית, כולל `ADMIN_TOKEN` שנוצר
אקראית.

אפשר גם להקים ידנית: `New → PostgreSQL`, ואז `New → Web Service` עם
`Root Directory: server`, `Build: npm install`, `Start: npm start`,
ומשתני הסביבה `DATABASE_URL` (מהמסד), `ORG_SLUG`, `ADMIN_TOKEN`
ו-`ALLOWED_ORIGIN`. מבנה הטבלאות ב-`server/schema.sql` מורץ אוטומטית
בכל עלייה של השרת.

**לחיבור מהמחשבון:** מסך ההגדרות ← טאב **מערכת** ← כתובת ה-API ומפתח
הגישה (`ADMIN_TOKEN`) ← "בדוק חיבור" לאימות, ואז "התחבר". הטאב גלוי
במחירון המאסטר בלבד.

### פרסום כתובת השרת לכל המיישמים

ההגדרות במסך שייכות לדפדפן שבו הוזנו. כדי שכל המיישמים יגיעו לשרת,
הכתובת חייבת להגיע אליהם מהאתר - היא נקראת מהשדה `backend` בקובץ
`pricing.json`:

```json
"backend": {
  "baseUrl": "https://oneflow-api.onrender.com",
  "orgSlug": "onebtn_team",
  "extraHeaders": ""
}
```

טאב **מערכת** מייצר את הקטע הזה מוכן להעתקה. זו פעולה חד-פעמית בהקמה.
**מפתח הגישה אינו נכלל בו** ואינו מתפרסם - הוא נשאר בדפדפן המאסטר בלבד.

מיישם שנכנס מקבל את הכתובת ואת מזהה הארגון, ופונה לשרת בלי מפתח.
לאחר אימות סיסמה מוצלחת השרת מנפיק לו אסימון כניסה אישי (תקף 30 יום),
הנשמר בדפדפן שלו בלבד ומוגבל למחירון שלו - הוא אינו יכול לגשת
למחירון של מיישם אחר, למאסטר (לכתיבה) או לרשימת הלידים.

### אבטחה בשרת

- סיסמה נשמרת כגיבוב `SHA-256` עם מלח, לעולם לא כטקסט גלוי. השרת
  אינו יכול לשחזר סיסמה קיימת - רק לאפס אותה לחדשה.
- כל בקשה נבדקת מול `x-org-slug`; בקשה ללא הכותרת הנכונה נדחית.
- הרשאות: המנהל (`ADMIN_TOKEN`) - גישה מלאה. מיישם מחובר - קריאה
  וכתיבה למחירון שלו ולאומדנים שלו בלבד, וקריאת המאסטר (לסנכרון).
  ללא אסימון - קריאת תקציר פומבי (שם ומצב) וקריאת המאסטר בלבד.
- השבתת מיישם (בטאב מיישמים) מבטלת מיידית את כל האסימונים הפעילים
  שלו, מעבר לחסימת כניסה חדשה.

## מחולל המחירונים

במחירון המאסטר, מסך ההגדרות ← "מחולל מחירונים למיישמים":

1. מזהה באנגלית (מופיע בקישור), שם המחירון, שם המיישם וסיסמה.
2. לחיצה על "צור מחירון" — נוצר העתק של המחירון הפתוח.
3. המסך מציג קישור וסיסמה להעתקה ומסירה למיישם.

הרשימה שמתחת מציגה את כל המחירונים הקיימים, ומאפשרת העתקת קישור,
קביעת סיסמה חדשה ומחיקה.

## סנכרון מול המאסטר

במחירון של מיישם מופיע הטאב **מחירון המאסטר**, ובו:

- מצב המאסטר, גרסתו ותאריך עדכונו.
- פירוט ההבדלים: מודולים שנוספו, מודולים שהוסרו, מודולים ששונו
  (שדה אחר שדה, לפני ואחרי) והגדרות ששונו.
- כפתור **סנכרן מחירונים** המאמץ את ערכי המאסטר ושומר גרסה חדשה.

מונה על לשונית הטאב מציג כמה הבדלים ממתינים. המערכת בודקת את המאסטר
ברקע כל שתי דקות.

## אומדנים על שם לקוח

בכל מחירון - מאסטר או מיישם - קיים טאב **האומדנים שלי**. בונים אומדן
במסך הראשי, ממלאים שם לקוח, ולוחצים **שמור אומדן על שם לקוח** בסרגל
הסיכום. האומדן נשמר עם כל הבחירות והסכומים באותו רגע, כך שגם אם
המחירון מתעדכן בהמשך, האומדן השמור משקף את המצב שבו הופק.

מהרשימה אפשר לפתוח אומדן קיים לעריכה (הכפתור בסרגל הופך ל"עדכן אומדן
שמור"), לשכפל אותו לאומדן חדש, או למחוק. **אומדן חדש** בטאב מנקה את
הבחירות הנוכחיות ומתחיל אומדן נפרד.

## לידים

במחירון המאסטר בלבד, טאב **לידים** מציג את כל האומדנים שנשמרו על ידי
כל המיישמים - לקוח, מיישם, תאריך יצירה ועדכון, וסכומים - ממוין מהחדש
לישן, עם חיפוש וסינון.

לקוח ששני מיישמים שונים בנו לו אומדן מסומן כ**"נבנה על ידי X מיישמים"**,
והאומדן הראשון שנוצר עבורו מסומן **"ראשון"** - לטובת שמירה מתחרות בין
מיישמים על אותו ליד.

## ניהול מיישמים

בטאב **מיישמים**, לצד כל מיישם: האם מוגן בסיסמה, כמה אומדנים בנה,
מועד הכניסה האחרונה שלו ומועד שינוי הסיסמה האחרון.

**קביעת סיסמה חדשה** - הסיסמה מוצגת פעם אחת להעתקה; אין דרך לשחזר
סיסמה קיימת, רק לקבוע חדשה. **השבתה** חוסמת כניסה חדשה ומבטלת מיידית
את כל הכניסות הפעילות של אותו מיישם; **הפעלה** מבטלת את החסימה, ולא
דורשת סיסמה חדשה.

## גרסאות

כל שמירה יוצרת גרסה הנושאת תיאור, מספר ותאריך. מסך ההגדרות מציג את
ההיסטוריה ומאפשר לשחזר כל גרסה. השחזור טוען את הגרסה לעריכה, והיא
נקבעת רק בשמירה — כך שהמצב הנוכחי אינו אובד בטעות.

## מודל התמחור

- **תמיכה ותחזוקה** — סכום חודשי לכל מודול נבחר.
- **מענק הקמה** — מכסת טרנזקציות חד-פעמית לכל מודול, ללא עלות.
- **חבילת טרנזקציות** — המכסה החודשית בפועל, נרכשת בנפרד.
- **משתמשים** — מכסה כלולה, וחבילות נוספות בתשלום.
- **הקמה** — סך שעות ההקמה של המודולים כפול תעריף השעה.
- **מינימום חיוב חודשי** — אומדן שנופל מתחתיו מחויב בסכום המינימום.

## פיתוח

אין תהליך בנייה. הקובץ `index.html` נטען ישירות בדפדפן ומקמפל JSX
בזמן ריצה. לצפייה מקומית יש להגיש את התיקייה דרך שרת HTTP פשוט —
פתיחה ישירה מהדיסק תמנע את טעינת קובץ המחירון.
